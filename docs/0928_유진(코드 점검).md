- 브랜치: `feat/develop-standby-service` (미커밋 상태에서 점검·수정)
- 기준 문서: `docs/0928_연서.md` (최종 방향성)
- 점검 대상: `python -m streamlit run streamlit_app.py` 통합 데모와 연결 코드
  (`odor_service/event_link/replay.py`, `odor_service/field/engine.py`, `administrative_agent/*`)
- 관련 상세 보고: `docs/0928_followup_review.md`(수정 상세·P0 비교), `docs/0928_A_limitations.md`(A안 한계 점검)
- 최종 상태: 방문 농가 후보를 **민원 위치 기준(A 절충안)**으로 바꿔 운영 replay·화면·문서에 적용 완료(4장)

## 1. 유지할 방향

이 서비스는 **발생원을 확정하는 시스템이 아니다.** 민원이 짧은 시간에 몰렸을 때 담당자가 확인할 권역과 농가의 순서를 좁혀 주는 현장 대응 지원 도구다.

```text
민원 집중 사건(EV2) → 추가 민원 예상 권역 Top 3 → 추천 대기 장소 → 방문 농가 후보 최대 5곳 → 현장 확인·시료 채취
```

- 농가 점수(100점) = 풍향 일치 40 + 거리 25 + 여러 민원 지점 일치 20 + 과거 반복 15
- 농가 점수는 발생원 확률이나 위반 판정이 아니다. 축종·사육 규모는 참고정보로만 쓴다.
- 금지 표현: "발생원 확률", "원인 농가 Top 5", "이 농가가 악취를 발생시켰다", "후보 안에 실제 발생원이 반드시 있다"

## 3. 고도화 내용

### 3-1. 사건 데이터 정합성

| 문제 | 수정 전 | 수정 후 |
|---|---|---|
| 사건 선택 방식 | 옛 EVT 사건(48개)을 시각이 가까운 EV2 사건에 연결. 2021년 사건 14개는 연결 실패, 4개 EV2 사건이 중복 연결 | EV2 재현 사건 136개를 직접 선택. 사건 ID가 같은 경우에만 연결하고 시간 근접 매칭은 삭제 |
| 초기 신고 수 | replay가 가축 민원만 사용해 "30분 내 5곳 이상" 사건인데도 5건 미만으로 표시된 사건이 56개 | 권역 모델과 같은 전체 익산 민원을 사용해 0개. 과거 반복 점수는 가축 민원 기준 유지 |
| 캐시 갱신 | `_revision` 인자가 Streamlit 캐시 키에서 빠져 replay 파일이 바뀌어도 화면이 갱신되지 않음 | `revision`으로 변경해 파일 변경 시 캐시가 갱신됨 |
| 문서와 화면 | 문서 생성 시 옛 모델의 사건·지표가 섞일 수 있음 | 문서의 사건 ID·기준시각·권역 좌표·기상을 화면과 일치시키고, 다른 모델 지표는 붙이지 않음 |
| 분석·예측 구간 | EV2 기준시각의 의미가 문서에 드러나지 않음 | 분석 구간(기준시각 전 30분)과 예측 구간(후 30분)을 표시 |

### 3-2. 행정 문서에 방문 농가 후보 연결

- 수정 전: 브리핑·점검 지시서에 권역 Top 3만 있고, 최종 방향의 핵심인 **방문 농가 후보가 빠져 있었다.**
- 수정 후:
  - `FieldCandidate` 모델을 추가해 화면 카드를 문서로 전달한다.
  - 브리핑·지시서에 "현장 확인 후보 농가" 섹션을 넣었다. 포함 항목은 순위, 묶인 농가명, 주소, 총점·항목별 점수, 선정 요약, 근사 좌표 경고, "발생원 확정 아님·경계 시료로 판단" 문구다.
  - 후보가 없으면 "조건에 맞는 방문 후보 없음"을 표시한다.
  - LLM 보정 결과에 금지 표현이 있거나 후보 섹션·권역 표가 바뀌면 안전 템플릿으로 되돌린다.
- 확인: 136개 사건 모두 화면 카드 수와 문서 후보 수가 일치했다.

### 3-3. 권역 점수와 대응 문구

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 상대위험점수 | 모델 점수×100이라 대부분 99/96/93 | 사건 내 상대 점수 100~60(예: 100/64/60) |
| 사이드바 표시 | "상대점수 99%" (바로 위의 "확률 아님" 문구와 모순) | % 표시 제거 |
| 대응 문구 | 80점 이상이면 모두 "가장 먼저 현장 확인" → 2·3순위에도 붙음 | 순위 기반: 1순위 "가장 먼저", 2·3순위 "1순위 확인 후 순차 확인" |

확인: 2·3순위에 "가장 먼저"가 붙은 사건 0개, 사이드바 % 표시 0개.

### 3-4. 기상·민원 정보 보강

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 상대습도·강수 | 모든 사건에서 "-" | AWS 702 사건 시각 정시 관측값을 replay에 저장. 136개 중 134개 채워짐(2개는 관측 없음, 카드 숨김) |
| 초기 신고 강도 | 저장되지 않아 "미제공" | replay에 저장해 지도 툴팁과 문서의 평균·최대에 표시 |
| 초기 민원 격자 수 | EV2 경로에서 "미제공" | 1km 격자 고유 개수를 계산해 표시 |
| 지역명 | 모두 null인데 문서에 빈 줄 표시 | 경계 파일이 없어 추정하지 않고, 값이 없으면 줄을 숨김 |
| 기상 안내 문구 | "기상정보는 모델 입력에 사용하지 않음" | "권역 예측 모델에는 미사용, 방문 농가 순위에는 풍향·풍속 사용" |

### 3-5. 화면(UI)과 운영 안정성

- "이후 신고" 지표: 항상 "—"로 나오던 것을 검증 토글을 켰을 때만 "Top 3 중 실제 이후 신고 권역 n/3"으로 표시한다.
- 시간대: 점검 입력 기본값과 지시시각을 `Asia/Seoul` 기준으로 통일했다(`administrative_agent/time_utils.py`). Streamlit Cloud는 UTC라 9시간 차이가 났다.
- 오류 표시: LLM 예외 상세는 로그로만 남기고, 화면에는 escape한 일반 안내만 표시한다.
- 사건 목록 시각을 `YYYY-MM-DD HH:MM` 형식으로 표시한다.
- 대기 장소 이름: IK-8 등 매핑이 없는 군집도 "OO 군집 방면"처럼 읽을 수 있는 이름으로 표시한다.
- 추천 대기 장소가 실제 GPS가 아닌 계산 출발점이라는 설명을 표시한다.

### 3-6. 점수 로직과 코드 정리

- 동명 농가 병합: 이름만 같으면 위치가 달라도 지우던 처리를 바꿨다. 같은 좌표이거나, 같은 이름이면서 300m 이내일 때만 묶고 묶인 ID·주소를 보존한다. 현재 데이터에서는 후보 결과가 달라지지 않았고(670→670), 별도 테스트로 동작을 확인했다.
- 과거 반복 15점은 후보 간 상대 정규화 값이라 최대 후보가 15점을 받는다는 점을 기준 문서에 명시했다.
- 덮어써지던 CSS(sticky/내부 스크롤)와 쓰이지 않는 Top 3 밖 권역 분기를 삭제했다.
- `replay.py`에서 실제 동작과 반대였던 김제 후보 주석을 바로잡았다.

### 3-7. 한계 명시 (코드 수정 대신 문서화)

- 대기 장소의 lift·등급·위치는 2020~2026 전체 자료로 계산돼 과거 재현에 이후 정보가 섞인다.
- 대기 장소 선정에 해당 밤 전체의 관측 평균 바람을 쓰므로, 사건 시점에는 알 수 없는 정보가 포함된다.
- `level`("출동")은 이후 7곳 사건까지 보고 붙인 **사후 확인 등급**이다. 화면과 문서의 출동 판단에는 쓰지 않는다.
- 농가 허가·좌표 정보가 과거 사건 당시 상태라는 보장이 없어 과거 발생원 검증에는 쓰지 않는다.

## 4. 방향성 핵심 과제: 농가 후보 탐색 기준 (P0 → A 절충안 적용)

### 4-1. 문제

이전에는 농가 후보를 **민원 위치가 아니라 추천 대기 장소 반경 4km 안에서** 뽑았다. 대기 장소는 밤 평균 풍향으로 정해져 민원 위치와 무관하다. 게다가 용지 대기 장소는 김제 용지 군집 옆이라, 같은 군집이 다시 1순위가 되는 순환 구조가 생겼다.

### 4-2. 비교 실험 (Codex, 기본 동작은 변경하지 않음)

| 안 | 20점 0점 카드 | 김제 대체 사건 | 카드–민원 중심 거리 | 익산 후보 있는 사건 |
|---|---:|---:|---:|---:|
| 현재 (대기 장소 기준) | 87.6% | 53.7% | 9.9km | 44.9% |
| A (민원 중심 기준) | 16.0% | 0% | 3.0km | 98.5% |
| B (대기 장소 유지·20점 재설계) | 38.1% | 53.7% | 9.9km | 44.9% |

A안이 방향에 맞지만, A안 한계 점검(`docs/0928_A_limitations.md`)에서 평균 중심 하나로는 흩어진 민원을 대표하지 못하고(36개 사건), 풍향에 민감하며, 이동 거리 문제가 남는다는 점이 확인됐다. Codex는 **민원 지점별 후보 합집합 + 2곳 이상 지지 우선(절충안)**을 권고했다.

### 4-3. 적용한 절충안 (`odor_service/field/engine.py`의 `score_complaint_candidates`)

| 단계 | 내용 | Codex 권고와의 관계 |
|---|---|---|
| 고유 민원 위치 | 30m 안 신고를 하나로 묶고, 대표점은 실제 신고 좌표(medoid) | 권고 그대로(반복 신고 중복 표 방지) |
| 위치별 풍상 탐색 | 각 민원 위치에서 풍상 ±45°·4km 안 농가의 합집합 | 권고 그대로(평균 중심 제거) |
| 교차 확인 우선 | 2곳 이상 지지 후보만 우선. 없을 때만 1곳 지지 후보를 `단일 지점 참고`로 제시. 5곳 억지로 채우지 않음 | 권고 그대로(절충안) |
| 관련성과 이동 분리 | 거리 25점을 "가장 가까운 지지 민원 위치와의 거리(민원 근접)"로 변경. 대기 장소는 방문 동선(가까운 곳부터) 계산에만 사용 | 권고 3번 반영(거리 축척 조정이 아니라 분리) |
| 민원 무리 대표 보장 | 2km 안으로 이어지는 민원 위치를 한 무리로 보고, 무리마다 최고 후보 1곳을 먼저 포함 | 권고에서 "별도 결정"으로 남긴 5개 제한 문제를 보완 |
| 풍향 민감도 표시 | 풍향 ±20°에서 후보 유지 비율을 `후보 안정성`(높음·보통·낮음)으로 표시, 50% 미만이면 경고 | 권고 4번 반영 |
| 풍향 결측 | 사건 시각 풍향이 없으면 밤 평균으로 채우지 않고 후보를 만들지 않음 | 권고 4번 반영(임의 풍향 금지) |

익산 우선·김제 대체, 과거 반복 15점, 300m 동명 병합, 최대 5곳 규칙은 유지했다.

### 4-4. 결과 (136개 사건 replay 재생성, 같은 기준으로 비교)

| 지표 | 이전 (대기 장소 기준) | 적용 후 (민원 위치 기준) |
|---|---:|---:|
| 카드 수 | 670 | 598 |
| 민원 중첩 20점이 0점인 카드 | 587 (87.6%) | 0 (0%) |
| 김제 대체 후보 사건 | 73 | 0 |
| 익산 후보가 있는 사건 | 61 | 134 (나머지 2개는 풍향 관측 없음) |
| 카드–민원 중심 거리 중간값 | 9.97km | 2.98km |
| 가장 가까운 지지 민원 위치까지 거리 중간값 | - | 2.45km |
| 교차 확인 / 단일 지점 참고 사건 | - | 130 / 4 |
| 후보 안정성 평균(풍향 ±20°) | - | 57% (낮음 35개, 높음 30개 사건) |
| 대기 장소→후보 직선 거리 중간값 | 1.93km | 9.03km |

예시 `EV2-0306`(2022-07-13): 이전에는 김제 용지면 농가 5곳(근사 좌표)이 나왔다. 적용 후에는 민원 위치 5곳 모두가 가리키는 익산 신흥동 농가 5곳이 민원 위치에서 2.1~2.7km 거리에 나온다.

- 20점 0점 카드가 사라진 것은 지지를 후보 자격으로 요구했기 때문이다. 이 자체를 성능 향상으로 주장하지 않는다.
- 대기 장소→후보 거리가 늘어난 것은 후보가 민원 쪽으로 옮겨졌기 때문이다. 대기 장소 선정이 민원 위치와 연결되지 않는 문제는 남아 있다(6장).

### 4-5. 화면·문서 반영

- 후보 카드에 `교차 확인 n/N` / `단일 지점 참고` 배지, 가장 가까운 민원 위치 거리, 대기 장소 직선 거리와 방문 동선 순서를 표시한다.
- 패널 상단에 풍속·풍향 신뢰도·후보 안정성, 고유 민원 위치 수와 민원 무리 수를 표시한다. 단일 지점 참고일 때는 경고를 띄운다.
- 카드 아래에 "방문 동선 제안(대기 장소 출발, 직선 거리 합계)"을 따로 표시해 관련성 순위(지도 숫자)와 구분한다.

## 6. 남은 작업

1. **대기 장소 선정을 민원 위치와 연결:** 후보는 민원 쪽으로 옮겨졌지만 대기 장소는 여전히 밤 평균 풍향으로 정한다. 대기 장소→후보 직선 거리 중간값이 약 9km다. 실제 담당자 위치·도로 이동시간을 확보해 방문 동선을 다시 계산해야 한다.
2. **약풍 사건 처리:** 풍속 1m/s 미만 사건이 61개(45%)다. 후보 안정성이 낮은 사건은 현장 풍향 확인 후 후보를 좁히는 절차를 운영 지침에 넣는다.
3. **4km·±45°·2km 무리·최대 5곳 기준 검증:** 운영 가정이며 실제 악취 수송 범위나 발생원 적중률로 검증한 값이 아니다.
4. **미래 정보 제거:** 대기 장소 lift·등급·위치가 2020~2026 전체 자료로 계산돼 있다. 사건 연도 이전 자료로 다시 만들어야 전향적 성능으로 말할 수 있다.
5. **현장 검증:** 현장 시료·점검 기록으로 방문 우선순위의 실제 유용성을 평가한다.
